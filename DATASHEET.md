# Datasheet — CareRoute triage dataset

Companion to [`MODEL_CARD.md`](MODEL_CARD.md). A model card documents the model; a
**datasheet documents the data it learned from** — the distinction Gebru et al.
(*Datasheets for Datasets*, 2018) draw and that XRAI Day 1–2 names alongside model
cards.

Every number here is **derived from `data/triage_dataset.meta.json`**, which is
regenerated by `python -m app.ml.export_dataset` and re-verified in CI by
`data:version --check`. `tests/test_datasheet.py` asserts this document and that
file agree, so a dataset change that is not reflected here fails the build.

## Motivation

**Why was it created?** To train and evaluate the severity classifier behind
CareRoute's triage recommendation, and to make that model's fairness auditable
against age and sex. It exists for an academic practice module.

**Why synthetic?** Real emergency-department triage records are patient data: they
cannot be committed to a student repository, redistributed to markers, or
regenerated by anyone reproducing this work. A seeded generator makes the whole
pipeline reproducible from source and removes every PDPA question from the
project's critical path.

**What that costs, stated plainly.** The generator encodes *our assumptions* about
how symptoms map to acuity. A model trained on it can only be as correct as those
assumptions, and the fairness results below measure fairness **with respect to a
distribution we wrote**. No claim is made that these numbers transfer to a real
population. This is the single biggest limitation of the project and is not
mitigable without real data.

## Composition

**What does an instance represent?** One synthetic patient presentation: binary
symptom flags, an age band, a sex, and a ground-truth acuity from P1
(resuscitation) to P5 (self-care).

**Label distribution** — deliberately imbalanced, because real triage is:

| Acuity | Rows | Share |
|---|---|---|
| P1 Resuscitation | 451 | 7.5% |
| P2 Emergent | 823 | 13.7% |
| P3 Urgent | 1804 | 30.1% |
| P4 Non-urgent | 1809 | 30.1% |
| P5 Self-care | 1113 | 18.6% |

**Subgroup distribution** — and here is the uncomfortable one:

| Age band | Female | Male |
|---|---|---|
| 0–17 | 881 | 933 |
| 18–39 | 877 | 894 |
| 40–64 | 869 | 830 |
| **65+** | **358** | **358** |

The 65+ band holds **~12% of the rows** while the other three hold ~29% each. That
under-representation is generated on purpose: it reproduces the real failure mode
this project exists to demonstrate, where the group with the highest clinical risk
contributes the fewest training examples and the model learns them worst. It is why
`app/ml/model.py` oversamples age bands to parity before training the deployed model,
and why **65+ Female remains the weakest subgroup** in the fairness audit (accuracy 0.7901,
against 0.8283 for 65+ Male and 0.90-0.95 for every other subgroup). 65+ Male was
also the subgroup whose emergencies the model missed most (red-flag recall 0.8966, 26 of
29, before `min_samples_leaf=5`; 0.9714 on the current model, n = 35). The oversampling duplicates the rare
elderly rows, and trees grown to one row per leaf memorised those duplicates.

**Is any of it patient data?** No. No real person is represented, and there is
nothing to de-identify.

**Missing values?** None — the generator emits complete rows. Real intake data
would not, and the serving path's feature builder must handle absence; that gap
between train and serve is a known risk, not something this dataset exercises.

## Collection process

Not collected — **generated**, by `app.ml.data.generate_dataset(n=6000, seed=42)`.
The function is the authoritative specification of the sampling: acuity priors,
per-acuity symptom probabilities, the age-band weights that produce the imbalance
above, and the age-adjustment rule that makes an identical symptom set more acute
in an older patient.

Because the seed is fixed and recorded in the metadata, the dataset is
**content-addressed**: `dataSha256` changes if and only if the data changes, and
`data:version --check` fails the pipeline on an undeclared change.

## Preprocessing / labelling

Labels are not annotated after the fact — they are the generator's ground truth,
so there is no inter-annotator disagreement to report and no label noise beyond
what the generator introduces deliberately.

**Split:** 75/25 train/test, **stratified** on acuity, `random_state=42`. Stratified
because P1 is only 7.5% of rows and an unstratified split can leave the test set
with too few resuscitation cases to measure red-flag recall meaningfully — the one
metric that gates a release.

**Rebalancing happens at training time, not here.** The stored dataset is the
imbalanced one; `build_artifact()` oversamples under-represented age bands to parity
for the deployed model, and trains the age-blind baseline on the raw split. Keeping
both in one dataset is what makes the before/after fairness gap a real comparison
rather than two unrelated runs.

## Uses

**Used for:** training the deployed RandomForest, the age-blind fairness baseline,
the drift reference distribution, the SHAP background sample, and the poisoning /
evasion / membership-inference security gates.

**Should NOT be used for:** any clinical claim, any epidemiological inference, or
any benchmark implying real-world triage accuracy. The distribution is invented.

**Tasks it is inappropriate for:** anything requiring free-text realism. The
`rawText` field is composed from a small phrase bank, so it is adequate for
exercising the intake and guardrail paths and useless for training a language model.

## Distribution and maintenance

Generated on demand from source; the repository stores the **metadata and hash**,
not a data file, so there is nothing to redistribute and nothing to drift.
Maintained with the codebase — the generator, this datasheet and
`triage_dataset.meta.json` change in the same commit or CI fails.

**Owner:** the CareRoute project team. **Licence:** follows the repository.

## Known limitations

1. **Synthetic throughout.** Every result is conditional on the generator's
   assumptions. See *Motivation*.
2. **65+ under-represented by design**, and the two 65+ subgroups are still the
   weakest after mitigation — documented rather than tuned away. Each 65+
   subgroup has only 29-40 held-out emergencies, so its red-flag recall moves
   2.5-3.5 points per case.
3. **A minor-trauma blind spot** found by evaluation E5 is deliberately left
   visible and un-gated; see the *Evaluation Plan* note in the vault.
4. **No missing values, no free-text realism** — both make the dataset easier than
   reality in ways that flatter the model.
